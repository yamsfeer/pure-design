# 设计术语入门（面向非设计背景的开发者）

> 这份文档写给不懂设计、但需要理解 pure-design 项目（以及上游 open-design）的开发者。
> 目标是建立基本概念：每个术语是什么、为什么存在、在项目里对应哪个文件/机制。
> 用程序员熟悉的类比讲解，避免设计圈黑话。

---

## 一、核心概念：三件套

### 1. 设计系统（Design System，简称 DS）

**是什么**：一套"品牌的视觉宪法"——这个品牌的产品长什么样：背景色、文字色、字体、圆角大小、按钮样式、间距、组件规范……全规定死。

**为什么需要**：一个品牌的产品可能有几十个页面，如果不规定统一规范，每个页面都会长得不一样。设计系统保证"看一眼就知道是这家公司的产品"。

**项目里的位置**：`assets/design-systems/<品牌名>/DESIGN.md`（共 151 个）

**程序员类比**：UI 框架的设计规范文档（如 Ant Design 的规范），但这里指的是**某一个品牌**的规范，不是通用组件库。

### 2. 品牌契约（Brand Contract）

**是什么**：设计系统落地成文件的那份"约定"。同一个东西的两种说法：
- **设计系统** = 概念本身（一套规范）
- **品牌契约** = 这套规范写成的规则文件（`DESIGN.md`），AI 和设计师都必须遵守

**为什么叫"契约"**：因为它像合同——AI 不能即兴发挥另造颜色，必须从这份文件里取。我们项目里的输出契约有明确要求："把 DESIGN.md 的配色精确映射到 `:root` 变量，不要另造 hex"。

**程序员类比**：接口规范。AI 是实现方，必须按接口来，不能自己发明接口。

### 3. 视觉调性（Visual Tone）

**是什么**：设计的"气质"——整体给人的感觉：奢华、极简、可爱、极客、严肃、温暖……

**与品牌的区别**（最容易混淆的一对）：
- **品牌** = 你是谁（Stripe = 支付公司）
- **调性** = 你说话的语气（同一个 Stripe，可以做得奢华、极简或可爱——气质不同，品牌不变）

**程序员类比**：品牌 = 公司名/域名；调性 = UI 的"人格"。

## 二、School（流派）

**是什么**：把"视觉调性"归类成几大派别。英文 school 直译"学派"，像艺术流派（印象派、野兽派）一样，每个流派有统一的气质特征。

**为什么存在**：调性无限多，但大部分可归入少数几个大类。归类后可以**为每个流派准备具体配方**（配色值、字体栈、布局规则），AI 选中一个流派就照配方执行，不用从零发明——这是"确定性优于即兴发挥"的关键。

**项目里的位置**：`assets/directions/`（5 个文件）

| School | 气质 | 类比 |
|---|---|---|
| editorial-monocle | 杂志、报纸、衬线字、大标题 | 《经济学人》 |
| modern-minimal | 极简、留白、无装饰 | 苹果官网 |
| tech-utility | 科技感、工具感、程序员气质 | 开发者工具后台 |
| human-approachable | 亲和、温暖、友好 | 社区类产品 |
| brutalist-experimental | 粗野、大胆、打破常规 | 实验艺术网站 |

每个 school 不只是气质描述，还带**具体配方**：配色值、字体栈、布局姿态、真实参考作品。

**程序员类比**：主题包 / theme preset（如 VS Code 的配色主题，选中即应用，不自己调）。

## 三、流程术语：Branch

**是什么**：来自上游规则代码的分支逻辑，没有任何设计含义，就是 if/else 分叉：

```
用户有没有提供品牌资料（品牌规范 / 参考网站 / 截图）？
    ├─ 有 → Branch A：AI 去抓取那个品牌的真实颜色/字体 → 写成品牌规范文件（brand-spec.md）
    └─ 没有 → Branch B：AI 自己从 5 个 school 里挑一个最搭的
```

**为什么分两支**：处理方式完全不同——用户给了品牌源，AI 要做"提取"（从 CSS/截图里抓真实值，禁止凭记忆编造）；没给，AI 要做"选择"（从方向库里挑最匹配的）。

**程序员类比**：`if (有品牌资料) { extractBrand() } else { pickDirection() }`

## 四、实现层术语（AI 执行设计时涉及）

### Token（设计令牌）

**是什么**：把具体颜色/字体/间距存成命名变量，如 `--bg: #FAFAFA`、`--accent: #c96442`。所有代码（CSS）通过变量名引用，不直接写死数值。

**为什么需要**：改一处全局生效；保证"同一套品牌"下所有页面取值一致；AI 可以"绑定"变量而不是每处重新发明颜色。

**程序员类比**：常量表 / 环境变量——`const ACCENT = '#c96442'`，别处引用 `ACCENT`。

### `:root`

**是什么**：CSS 里定义这些变量的"全局作用域"。设计系统/方向选中后，AI 把配方映射到 `:root` 块里。

**程序员类比**：全局变量的声明文件。

### OKLch

**是什么**：一种颜色表示法（类似 RGB / HEX），但更符合人眼感知的均匀性——同等数值变化，人眼看到的变化幅度一致。

**为什么上游坚持用它**：RGB 里"加 10"在不同的色相上，人眼感知差异可能很大；OKLch 更科学。调色时用 OKLch 能精确控制"明度、彩度、色相"三个独立维度。

**需要掌握的程度**：不需要。知道"是一种更科学的颜色编码"即可，遇到 OKLch 数值（如 `oklch(68% 0.16 220)`）就当作颜色值处理。

### Craft（工艺参考）

**是什么**：设计领域的"基本功手册"——排版规则、配色规则、无障碍规范（对比度、可读性）、反 AI 味原则等。独立于品牌，任何项目都适用。

**项目里的位置**：`assets/craft/`（13 个文件，如 typography、color、anti-ai-slop、accessibility-baseline）

**程序员类比**：编码规范 / style guide（如 Airbnb 的 JavaScript Style Guide）——不分项目，照着写就合格。

### Template（渲染模板）

**是什么**：页面骨架（HTML 框架），AI 往里面填内容。模板定义了结构（头部/导航/区块），保留 class 系统与 CSS 变量。

**项目里的位置**：`assets/design-templates/<模板名>/`（114 个），每个含 `SKILL.md`（契约）+ `assets/template.html`（骨架）+ `references/`（布局库、自检清单）

**程序员类比**：项目脚手架（scaffold）——先搭好骨架再填业务。

### Skill（技能）

**是什么**：AI 的工作流/方法论——针对某类任务的一组指令（怎么做这件事）。例如 frontend-design 技能规定"先定视觉方向 → 写完整 HTML → 对照自检清单审查"。

**项目里的位置**：`assets/skills/`（162 个）

**关键**：skill 是 **AI 的工具**，不是用户的配置项——理想情况下用户不需要关心用了哪个 skill。

**程序员类比**：工具函数 / 插件——按需调用，各有职责。

## 五、一张图理清全部关系

```
                ┌─────────────────────────────────┐
                │      品牌（你是谁）              │
                │   设计系统 = 品牌视觉宪法          │
                │   DESIGN.md = 契约（规则文件）     │
                │   Token = 契约里的具体数值（变量） │
                └───────────┬─────────────────────┘
                            │  （用户定，或 default）
                            ▼
                ┌─────────────────────────────────┐
                │      调性（你说话的语气）          │
                │   5 个 School（流派）            │
                │   editorial / minimal / tech    │
                │   / human / brutalist           │
                └───────────┬─────────────────────┘
                            │  （AI 自选或用户选）
                            ▼
                ┌─────────────────────────────────┐
                │      工作流（怎么做这件事）        │
                │   Skill = AI 的技能/方法论         │
                │   Craft = 基本功手册（通用）       │
                │   Template = 页面骨架             │
                │   :root = 变量挂载点              │
                └─────────────────────────────────┘
```

**一句话总结**：品牌（DS + Token）决定"用什么颜色和字体"，调性（School）决定"整体气质"，工作流（Skill + Craft + Template）决定"AI 用什么方法做"，三者按顺序依次确定，后面的依赖前面的。

## 六、常见问题

**Q: 设计系统和视觉调性会不会冲突？**
A: 会，但上游用"优先级"解决：品牌契约（DESIGN.md）为准，调性只决定"气质方向"（比如用不用衬线、留白多少），不能推翻品牌的颜色/字体。我们项目里视觉方向（direction）会"覆盖设计系统的配色/字体"，但要照抄 `:root` 值、不即兴发挥。

**Q: 为什么不让 AI 直接自由发挥设计，非要这些规则？**
A: 三个原因：① 一致性——同一品牌多个页面要长得像；② 可解释性——用户能知道"为什么是这种风格"（因为选了 Stripe 系统 + editorial 方向）；③ 反 AI 味——自由发挥容易产出千篇一律的"AI 味"设计，规范约束反而出好东西。

**Q: 151 个设计系统里，default 是什么？**
A: 一个中性的"入门款"（Category: Starter）——没有特别气质，适合任何不要求特定风格的场景，是所有设计的兜底默认值。
